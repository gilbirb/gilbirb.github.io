# **Rust**

## **What is it?**
***

Rust is a systems programming language that aims to give you:
* C/C++-level performance - no garbage collector, minimal runtime, zero-cost abstractions.
* Memory safety without a garbage collector - enforced entirely at compile time via the ownership and borrowing system
* Fearless concurrency - the same rules that prevent memory bugs also prevent most classes of data races, checked by the compiler
* Modern tooling - `cargo` (build system + package manager), `rustfmt` (formatter), `clippy` (linter) are all first-party and standard

Instead of relying on the programmer (or a garbage collector) to manage memory correctly, Rust's compiler statically proves a set of rules are followed. If your code compiles, whole categories of bugs (use-after-free, double-free, null pointer dereference, data races) are eliminated before the program ever runs.

This is the trade-off: Rust pushes work from "runtime debugging" to "compile-time fighting the borrow checker."

## **Compilation Model**
***

* Rust is ahead-of-time (AOT) compiled via `rustc`, producing a native binary unlike interpreted (Python) or JIT-compiled (JVM) languages.

* Statically typed: every variable's type is known at compile time. Type inference means you often don't have to write types explicitly, but they still exist and are checked.

* No `null` in safe Rust - instead, absence is represented explicitly via `Option<T>`. This removes an entire class of null-pointer bugs by making "might not have a value" part of the type system.

* No exceptions - recoverable errors are represented via `Result<T, E>`, not thrown/caught. Unrecoverable errors use `panic!`.

## **Cargo**
***

`cargo` is Rust's package manager and build system, roughly analogous to `npm/pip` + a build tool.

| Command | Purpose |
| ------- | ------- |
| cargo new <name> | Scaffold a new binary project |
| cargo build | Compile the project (debug mode by default) |
| cargo add <dependency> | Adds a dependency to your project's `Cargo.toml` |
| cargo remove <dependency> | Remove a dependency |
| cargo run | Compile and run |
| cargo build --release | Compile with optimizations |
| cargo check | Type-check without producing a binary (fast feedback) |
| cargo test | Run tests |
| cargo fmt | Auto format code |
| cargo clippy | Linter |

* Cargo.toml - The configuration file for the project. It declares intent: what your project is called, what dependencies it wants, and various metadata.
* Cargo.lock - This file is auto-generated by Cargo and records the exact resolved version of every dependency (and their transitive dependencies) that was actually used to build the project.

Analogy using `npm`: `Cargo.toml` ≈ `package.json`, `Cargo.lock` ≈ `package-lock.json`
